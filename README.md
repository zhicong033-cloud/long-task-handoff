# long-task-handoff

一个 Claude Skill：长任务对话变长时，写一份交接文档并建议开新会话继续。

## 为什么

LLM 对话每一轮都会把全部历史重发一遍，所以一条会话的总成本大致正比于**轮次的平方**，
而不是轮次本身。

在一个真实账户上实测（7,577 次请求）：

| 轮次 | 该轮平均携带的上下文 |
| --- | ---: |
| 第 1–10 轮 | 41,430 |
| 第 11–30 轮 | 72,700 |
| 第 31–100 轮 | 118,458 |
| 第 100 轮以后 | 138,666 |

**第 100 轮之后的一次提问，成本是前 10 轮的 3.3 倍**，而问题本身可能一样简单。
同一账户里，13 条超过 100 轮的会话吃掉了 90.2% 的 Token。

重开一条会话把起点拉回四万左右。交接文档本身几乎不花钱——写它的时候上下文
已经在内存里，成本只是几千 Token 的输出。

## 它做什么

1. **在任务边界提议收尾**，而不是数到 30 轮就砍；
2. **写一份让重开变便宜的交接文档**（现在在做什么 / 已完成 / 卡在哪里 / 下一步 / 哪些坑不要踩）；
3. **给出新会话的第一条消息**——这一步最容易被跳过，但它决定了新会话从多高的上下文起步。

## 它刻意不做什么

- 不在你正调一个还没定位的 bug 时打断你（现场信息压缩不进文档，硬切反而更贵）；
- 不替你结束会话；
- 提过一次就不再唠叨。

## 安装

把 `SKILL.md` 放进你的 skills 目录，或者打包成 `.skill` 文件后在 Claude 里保存。
